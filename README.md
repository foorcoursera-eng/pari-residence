# PARI Residence — сайт

Жилой квартал премиум-класса в Самарканде. Статический сайт (RU + UZ) плюс одна
serverless-функция для приёма заявок. Никаких фреймворков на странице: весь JavaScript —
21 КБ собственного кода, поэтому сайт быстро открывается на телефоне.

## Как всё устроено

```
src/content.js      все тексты и данные проекта (RU + UZ) — единственный источник правды
src/templates.js    шаблоны страниц: шапка, меню, форма, тела разделов
build.js            сборка: страницы → dist/, плюс sitemap.xml и robots.txt
check.js            проверка собранного: битые ссылки, h1, метаданные, alt, дубли id
test/lead.test.js   проверка приёма заявки (сеть подменяется, наружу ничего не уходит)
api/lead.js         приём формы: валидация, ловушка для ботов, лимит запросов
lib/crm/            слой доставки заявки: telegram.js, macro.js, normalize.js
assets/             шрифты, изображения (webp), видео первого экрана
styles.css          фирменный стиль по гайдбуку PARI
script.js           видео-петля, бабочки, меню, аналитика, UTM, формы, карта
```

Команды:

```bash
npm run build     # собрать сайт в dist/
npm run check     # проверить собранное
npm test          # проверить приём заявки
npm run verify    # всё сразу — это же гоняет CI перед публикацией
npm run serve     # локальный просмотр на http://localhost:5174
```

## Видео первого экрана

Петля смонтирована из имиджевого ролика клиента и лежит в трёх вариантах:
`hero-loop-1920` (6,6 МБ) для широких экранов, `hero-loop-1280` (3,3 МБ) для остальных
и вертикальная `hero-portrait` 720×1280 (1,4 МБ) для телефонов. Вариант выбирает
`script.js` по ширине окна; на телефоне загрузка начинается после полной отрисовки
страницы, чтобы не мешать первому экрану. Петля не грузится вовсе при включённой
экономии трафика, на 2G и когда в системе выключены анимации — тогда остаётся
кадр-постер.

Адреса страниц заданы в `src/content.js` → `routes`. Новый раздел добавляется
шаблоном в `src/templates.js` и строкой в `pagesFor()` внутри `build.js` — карта сайта,
hreflang и хлебные крошки соберутся сами.

## Публикация

Vercel собирает проект сам: `buildCommand: node build.js`, `outputDirectory: dist`
(см. `vercel.json`). Функция `api/lead.js` деплоится отдельно и доступна по `/api/lead`.

### Переменные окружения

Задаются в настройках проекта на Vercel (Settings → Environment Variables).
**В код и в git они не попадают.**

| Переменная | Обязательна | Зачем |
|---|---|---|
| `TG_BOT_TOKEN` | да | токен бота, который присылает заявки менеджеру |
| `TG_CHAT_ID` | да | чат или группа отдела продаж |
| `MACRO_API_URL` | нет | адрес метода создания заявки в MacroCRM |
| `MACRO_DOMAIN` | нет | домен аккаунта в CRM |
| `MACRO_APP_SECRET` | нет | секрет приложения |
| `MACRO_AUTH` | нет | `md5` (по умолчанию) или `bearer` |

Пока переменных MacroCRM нет, заявки уходят только в Telegram — форма при этом работает.

## Что нужно получить от администратора MacroCRM

Интеграция написана как слой абстракции (`lib/crm/macro.js`) и включится сразу, как
появятся ответы на эти вопросы. Ничего из перечисленного мы не додумывали.

1. Название и версия CRM, ссылка на документацию API.
2. Базовый адрес API и метод создания заявки.
3. Способ авторизации: подпись (домен + время + секрет) или Bearer-токен.
4. Тестовый контур или тестовый аккаунт.
5. Полный список обязательных полей заявки и их точные названия.
6. Формат запроса (form-urlencoded или JSON) и формат ответа.
7. Возвращается ли идентификатор созданной заявки.
8. Поддерживаются ли поля источника: `utm_source`, `utm_medium`, `utm_campaign`,
   `utm_content`, `utm_term`, страница входа, реферер.
9. Правила дедупликации по номеру телефона — объединяет ли CRM повторные обращения.
10. Можно ли назначить ответственного менеджера и как передать проект/объект.
11. Есть ли webhook об изменении статуса заявки.
12. Ограничения по частоте запросов.
13. Методы получения объектов недвижимости и их статусов (`available`, `reserved`, `sold`),
    если каталог квартир на сайте понадобится позже.

## Аналитика

Счётчики не подключены — идентификаторов пока нет. Код уже отправляет события в
`window.dataLayer` и вызывает `ym`/`gtag`, если они появятся на странице:

`page_view`, `cta_click`, `phone_click`, `map_click`, `lead_form_open`,
`lead_form_submit`, `lead_success`, `lead_error`.

Чтобы включить Метрику или GA, достаточно вставить код счётчика в `src/templates.js`
(в `shell`) и задать `window.PARI_ANALYTICS = { metrika: НОМЕР }` — менять логику страниц не нужно.

## Переключение на домен pari-residence.uz

Домен пока не привязан: DNS не отвечает, поэтому `canonical`, `og:url`, карта сайта
и микроразметка указывают на рабочий адрес `pari-residence.vercel.app`. Иначе поисковики
получили бы ссылки на несуществующий хост.

Порядок переключения:

1. Vercel → Settings → Domains → добавить `pari-residence.uz` и `www.pari-residence.uz`.
2. У регистратора домена прописать записи, которые покажет Vercel (обычно `A 76.76.21.21`
   для корня и `CNAME cname.vercel-dns.com` для `www`).
3. Дождаться, пока домен ответит по HTTPS (сертификат Vercel выпустит сам).
4. Vercel → Settings → Environment Variables → добавить `SITE_ORIGIN` =
   `https://pari-residence.uz` и запустить Redeploy.
5. В Vercel сделать `pari-residence.uz` основным доменом — старый адрес будет
   переадресовывать на него.
6. В Google Search Console и Яндекс Вебмастере добавить новый домен и отправить
   `https://pari-residence.uz/sitemap.xml`.

После шага 4 все адреса в разметке и карте сайта переключатся сами: адрес собран
из одной переменной, править код не нужно.

## Служебные скрипты

- `python tools/make-plans.py` — нарезает планировки из **векторных рабочих
  листов застройщика** (`Блок 1 и Блок 1.1.pdf`, `Блок 2 и Блок 2.1.pdf`,
  `Блок 2.2.pdf`, `Блок 3..pdf`, `Блок 3.1..pdf`). Это лучший источник: чертёж
  там не картинка, поэтому рисуется в любом размере без замыливания, а текстовый
  слой даёт площадь квартиры — по ней лист и находится, вручную страницы не
  перечисляются. На каждую квартиру получается два файла: `<id>-1400.webp` — лист
  целиком (его открывает просмотрщик: чертёж, экспликация по комнатам, роза
  инсоляции, расположение на этаже и в комплексе) и `<id>-800.webp` — только
  чертёж, он стоит в карточке. Границы чертежа ищутся по самому крупному связному
  пятну чернил: раскладка листов плавает — роза стоит то справа, то под планом.
  Шапка листа обрезается намеренно, см. ниже. Планировка 95,13 м² (блок 4) берётся
  из буклета: этого листа застройщик не присылал, поэтому она чуть мягче
  остальных. Пути переопределяются переменными `PARI_SHEETS` и `PARI_BOOK`.
- `python tools/make-images.py` — готовит кадры фасадов, входной группы, двора
  и камня из рендеров 5504×3072, а также мастер-план района и вид сверху из
  буклета. Папка с рендерами задаётся переменной `PARI_RENDERS`.
- `python tools/make-promo-loop.py` — собирает петлю первого экрана
  (`assets/video/promo-hero-{1280,1920,2096}.{mp4,webm}`) из бренд-фильма
  `PARI_2400x1200_2.mp4`: двор, аркада, входная группа, лобби, общий план.
  Какие куски взяты и почему — списком `CUTS` в самом скрипте, там же причины
  выбора частоты и ступеней. Верхняя ступень 2096 — родная ширина исходника,
  выше поднимать нечего. Исходник в репозиторий не кладём: 239 МБ.
- `node tools/make-shots.js` — готовит в `dist/_shot/` копии страниц для съёмки
  скриншотов: анимации показаны в конечном состоянии, картинки грузятся сразу,
  вьюпортные высоты нейтрализованы. Нужен только для снятия кадров, на сайт не попадает.
- `python tools/make-og.py` — собирает `assets/img/og-cover.jpg` (1200×630) из
  `opening-shot-2560.webp`. Нужен для превью ссылок: Telegram и ВКонтакте не
  разворачивают WebP в `og:image`, а в Узбекистане ссылку чаще всего пересылают
  именно в Telegram — вместо кадра выходил пустой прямоугольник. Перезапускать
  только если сменился первый кадр главной.
- `python tools/add-okina.py assets/fonts/*.woff2` — добавляет в шрифты знак `ʻ`
  (узбекская окина в `oʻ`, `gʻ`). В исходных файлах его не было, из-за чего каждое
  узбекское слово с этим знаком добиралось системным шрифтом. Новый глиф не рисуется:
  в cmap добавляется ссылка на уже имеющийся знак `‘`. Скрипт уже применён; повторно
  нужен, только если шрифты придут заново от поставщика — и тогда лучше сразу попросить
  у него версию с U+02BB.

## Планировки

Шапка рабочего листа («2-х КОМНАТНАЯ КВАРТИРА, 43,3 м²») на сайт не выводится:
на листе блока 1, стр. 1 она противоречит собственной экспликации — написано
45,34 м², а комнаты в сумме дают 27,21 м². Экспликация верна, шапка — опечатка
застройщика (остальные 52 листа сходятся). Площадь под планом на сайте берётся
из `planItems`, а он сверен с экспликацией и буклетом.

Список планировок — `planItems` в `src/content.js`, общий для обоих языков.
Одна карточка на одну площадь: в буклете одна и та же площадь повторяется
в нескольких блоках зеркально, поэтому блоки перечисляются в карточке
(`blocks`), а не размножают её. Идентификатор совпадает с именем файла
в `assets/img/plans/`, поэтому список и картинки правятся вместе:
поменяли `PLANS` в `tools/make-plans.py` — поменяйте и `planItems`.

## Что держит сайт в поиске

Всё перечисленное собирается автоматически и проверяется `node check.js` —
руками править собранный `dist/` не нужно.

- **Состав дома лежит в разметке, а не только в JSON.** Это главное правило
  раздела квартир. Подбор на `/select/` читает `flats.json` скриптом — робот
  видел страницу без единой площади. Теперь настоящие цифры (сколько квартир,
  каких площадей, на каких этажах, во скольких подъездах) печатаются сводкой
  на пяти страницах по комнатности. Считает их `src/flats.js` → `stats()` из
  тех же 1186 записей, что и подбор, поэтому цифра на странице не может
  разойтись с цифрой в фильтре. Группа попадает на сайт, только если такие
  квартиры в шахматке есть: адреса заданы в `ROOM_GROUPS` (`src/templates.js`).
  **Сводкой, а не поштучно** — и это ограничение от заказчика, а не забытая
  работа. Раньше здесь стояла таблица «Где в квартале» с разбивкой по всем
  тринадцати подъездам и подпись, из какой выгрузки она взята; и то и другое
  снято 09.09.2026: покупателю не показывают шахматку целиком и не называют
  ни CRM, ни номер дома в ней (провенанс живёт комментарием в `src/flats.js`,
  в `flats.json` его нет). По той же причине листов планировок на странице
  комнатности не больше четырёх — `PLANS_SHOWN` в `src/templates.js`;
  двухкомнатных листов двадцать четыре, и страница из них не кончалась.
  Полный набор чертежей остаётся в каталоге `/apartments/`, конкретные
  квартиры — в подборе `/select/`.
- **Тексты для поиска.** `title` и `description` каждой страницы лежат в
  `src/content.js` → `meta`. Слова «новостройка», «купить квартиру»,
  «от застройщика», «рассрочка» стоят там потому, что именно ими люди
  в Самарканде описывают то, что ищут, и потому что всё это правда о проекте.
  В узбекских текстах рядом с адабий «xonadon» стоит разговорное «kvartira» —
  в поиске пишут второе. Перечислять ключевые слова подряд нельзя.
- **Вопросы и ответы.** Пары «вопрос — ответ» лежат в `ru.faq.items` / `uz.faq.items`
  с подстановками вида `{price}`, `{months}`, `{stage1}`. Подставляет их
  `facts()` в `src/templates.js` из `site` — поправили цену или срок в одном
  месте, поменялось и на странице, и в разметке `FAQPage`. Разметка обязана
  дословно совпадать с напечатанным текстом; `check.js` это сверяет и роняет
  сборку при расхождении.
- **Микроразметка.** `Organization`, `WebSite`, `ApartmentComplex` (главная),
  `WebPage` (везде), `BreadcrumbList` (внутренние), `RealEstateAgent`
  (контакты), `FAQPage` (вопросы). Собирается в `build.js`. Ничего
  неподтверждённого в неё не попадает: рейтингов и отзывов там нет, цена
  отдаётся как цена за квадратный метр, а не как стоимость квартиры.
- **Превью ссылки.** `og:image` — только JPEG `og-cover.jpg`, см. `tools/make-og.py`.
  `check.js` роняет сборку, если туда вернётся WebP.
- **Страница без JavaScript.** `.reveal` держит блоки на `opacity:0`, пока их не
  покажет скрипт. Правило в `<noscript>` возвращает их на место: Google скрипты
  исполняет, Яндекс — далеко не всегда, и одна ошибка в скриптах иначе гасит
  всю страницу. Проверяется на каждой странице.
- **`robots.txt` и карта сайта.** Пишутся в `build.js`. У Яндекса отдельный блок
  ради `Clean-param`: без него каждая ссылка с utm-метками заводится как
  отдельная страница. Ассеты не закрыты сознательно — закрытые CSS и скрипты
  не дают роботу отрисовать страницу. В карте есть `lastmod` и полный набор
  `hreflang` (`ru`, `uz`, `x-default`).

## Данные, которые нельзя выдумывать

В `src/content.js` собраны только подтверждённые сведения. Если данных нет —
они не публикуются, а попадают в список выше. Это касается цен, сроков сдачи,
рейтингов, отзывов и характеристик квартир.
